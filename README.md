# I2C_MemoryMap ツール

Saleaeのロジックアナライザ(Logic 2アプリ)で取得したI2C通信ログ(CSV)を読み込み、I2Cデバイス毎のレジスタ空間（Write / Read別）の遷移をImGui上のメモリビューアで視覚的に解析・再生するためのツールです。

---

## 📁 フォルダ構成

配布パッケージ内には以下のファイルが含まれています。

* **`i2c_memorymap.exe`** : メインプログラム
* **`devices/`** : デバイス定義ファイル（JSON）を格納するフォルダ
* **`sample_CSV/`** : サンプルデータ置き場

---

## 🛠️ 使い方

### 1. I2Cログファイル取得

Logic 2アプリからI2CログのCSVファイルを出力します。出力時の設定は以下に合わせてください。

* **`Columns`**: All
* **`Data`**: 任意
* **`Export Format`**: CSV
* **`User ISO8601 Timestamps`**: 使用しない
※確認時点のLogic 2アプリバージョン 2.4.46

### 2. デバイス設定の配置 (`devices/` フォルダ)

`devices/` フォルダ内にデバイス設定ファイル(JSON)を配置します。フォルダ内に配置されたすべての JSON ファイルが読み込まれます。JSONの詳しい記述仕様は**付録**を参照してください。

### 3. 起動とCSVファイル選択

1. **`i2c_memorymap.exe`** をダブルクリックして起動します。
2. 起動直後にファイル選択ダイアログが開くため、解析したい **I2CログのCSVファイル** を選択します。
サンプルのCSVは`sample_CSV`フォルダにあります。
3. ウィンドウが立ち上がり、タイムライン操作や各デバイスのWrite/Readメモリマップの確認が行えるようになります。

### 4. 操作方法

* **タイムライン移動**: 画面下部のコントロールパネルにあるスライダー、または `<< Prev` / `Next >>` ボタンでタイムスタンプ単位のステップ移動が可能です。
* **キーボード操作**: キーボードの **← / → 矢印キー** でも前後のデータにすばやく移動できます。

## 📌 付録：デバイス定義 JSON 仕様詳細

`devices/` フォルダ内に配置するJSONファイルのフォーマットおよび各設定項目の詳細です。独自のデバイスを追加・定義する際にご参照ください。

#### デバイス定義 JSON のフォーマット例

```json
{
  "devices": [
    {
      "name": "HDCP_Port_Primary",
      "dev_addr_7bit": "0x3A",
      "reg_addr_width": 1,
      "endian": "little",

      // ▼ 動作モード・挙動制御
      "auto_addr_inc": false,
      "support_direct_read_from_default_reg": true,
      "default_reg_addr": "0x08",

      // ▼ レジスタマップ定義
      "registers": [
        {
          "address": "0x00",
          "name": "Bksv",
          "bits_read": [
            { "byte_offset": 0, "bit_offset": 0, "width": 8, "name": "Bksv[7:0]" }
          ]
        }
      ]
    }
  ]
}

```

#### 各設定項目の詳細

##### 1. 基本情報

* **`name`**: デバイスの表示名（ウィンドウタイトルやタブに反映されます）
* **`dev_addr_7bit`**: 7ビットI2Cアドレス（16進数文字列、例: `"0x3A"`）
* **`reg_addr_width`**: レジスタアドレスの幅（バイト数、`0`～`4`まで対応）
* **`endian`**: マルチバイトデータのエンディアン（ビット定義を行っている場合に適用されます。現在`"little"`のみ対応。）

##### 2. 動作モード・挙動制御 ⚙️

* **`auto_addr_inc`**: アドレスの自動インクリメントの有無（`true` / `false`、reg_addr_widthが1以上の時に有効。メモリマップ的なデバイスは`true`、コマンドIDに複数バイト紐づくデバイスは`false`とする）
* **`support_direct_read_from_default_reg`**: アドレス指定なしのダイレクトリード時に特定アドレスのレジスタ値が読み出されるかどうか（`true` / `false`、通常のデバイスは`false`とする）
* **`default_reg_addr`**: ダイレクトリード時やリセット時に参照されるデフォルトアドレス（16進数文字列、support_direct_read_from_default_regが`true`の場合のみ有効）

##### 3. レジスタマップ定義 (`registers`)

デバイスが持つレジスタのリスト。各レジスタは以下のプロパティを持ちます。

* **`address`**: レジスタのアドレス（16進数文字列、例: `"0x00"`）
* **`name`**: レジスタの名称（例: `"Bksv"`, `"Ri'"`）
* **`bits`**: 読み出し（Read）、書き込み（Write）共通のビットフィールドの配列（省略可能）
* **`bits_read`**: 読み出し（Read）用ビットフィールドの配列（省略可能）。`bits`の定義よりも優先して適用されます
* **`bits_write`**: 書き込み（Write）用ビットフィールドの配列（省略可能）。`bits`の定義よりも優先して適用されます

##### 4. ビットフィールド定義 (`bits_read` / `bits_write`)

各レジスタ内に存在するビット単位・バイト単位のデータ構造を定義します。レジスタビュー上で、どの位置がどのデータに対応しているかを可視化するために使用します。

**ビットフィールドの各要素（オブジェクト）の構成:**

* **`byte_offset`**: レジスタ先頭からのバイトオフセット（例: `0` はレジスタの先頭バイト、`1` は次のバイト）
* **`bit_offset`**: 指定バイト内の開始ビット位置（`0`～`7`）
* **`width`**: ビット幅（例: 1バイト分なら `8`、複数バイトをまたぐ指定も可能です）
* **`name`**: 各ビットフィールドのラベル（例: `"Bksv[7:0]"` やステータスフラグ名など）
